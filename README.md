# Flow · 项目管理系统

一个单人本地项目管理工具，使用原生 HTML/CSS/JavaScript、Python 标准库和 SQLite 实现。不需要安装第三方运行依赖，也不需要前端构建。

## 功能与布局

- 仪表盘：任务完成率、逾期任务、项目进度、近七天完成趋势、最近动态，以及需求和缺陷摘要。
- 项目工作台：同一工作台内切换“计划管理 / 需求管理 / 缺陷管理”，不为每个功能增加侧栏入口。
- 计划管理：复用原有任务，支持列表、拖拽看板、甘特图三种视图；负责人、优先级、状态、起止时间、进度、搜索筛选、排序分页及批量操作。
- 甘特图：直接使用计划任务的起止日期；日 / 周 / 月尺度、时间段切换、定位今天、进度条和点击编辑。未排期任务保留可见，超出当前区间的任务可定位。
- 需求管理：需求背景、所属项目、负责人、优先级、状态、截止日期与验收条件；增删改查、筛选、分页和批量状态 / 删除。
- 缺陷管理：问题描述、复现步骤、发生环境、预期和实际结果，独立记录严重程度与优先级；支持修复、验证、关闭和重新打开。
- 新增与编辑使用弹窗，搜索筛选留在列表工具栏；项目内切换页签时保持项目范围。
- 三种主题、响应式布局、输入校验和空状态；SQLite 持久化、JSON 备份恢复、并发修改冲突保护。
- GitHub 工作台：个人仓库、分支与源文件浏览，提交历史及 diff，仓库项目关联与最近提交跟踪。

甘特图是计划管理里的视图，不是另一套任务数据。本版不自动计算依赖、关键路径或按提交次数完成任务；不加入团队账号、审批或工时系统。

## 快速开始

需要 Python 3.10 或更新版本。

```powershell
git clone https://github.com/Sarfffff/Project-flow.git
python -B ./Project-flow/src/server.py --port 58061
```

浏览器打开 [Flow 项目工作台](http://127.0.0.1:58061/project-flow/#tasks)。Windows 也可在项目目录双击“打开Flow.cmd”。停止服务时按 Ctrl+C。

首次启动自动创建空数据库，不附带示例项目、任务、需求或缺陷。系统需要 Python 后端，不能直接双击 HTML 使用，也不能仅部署到 GitHub Pages。

现有安装升级时，先导出完整工作空间备份，停止服务，再更新源码并重启、刷新页面。新需求和缺陷表自动建立，不重建原项目与任务表，不更改已设置的数据库位置。不要用分发包替换或删除已有 `data` 目录。

## GitHub 工作台

进入“工作空间设置 → 配置 GitHub 连接”。公开模式输入个人用户名；私有模式输入 Fine-grained token，可留空用户名自动识别账号。仅选择所需仓库并授予 Contents / Metadata 的 Read-only 权限。

验证成功立即生效，无需重启服务。令牌仅保留在后端进程内存，不回显、不写浏览器存储、数据库或备份；服务重启后需在设置中重新输入。不要将令牌发到聊天或写入源码。切换账号、断开连接保留已有仓库关联与提交快照；断开不等于在 GitHub 撤销授权。

工作台每 5 分钟自动同步仅在页面可见、已勾选时运行。跟踪快照最多 100 条，更早提交可在线分页查看。

## 结构

```text
Project-flow/
  README.md         仓库首页
  使用说明.md       完整使用、备份与测试说明
  打开Flow.cmd      Windows 唯一启动入口
  src/              前后端源码与运行依赖说明
  tests/            后端集成测试及前端逻辑检查
  文档/             产品需求与验收记录
  data/             首次运行自动生成，不纳入 Git
```

管理模块主要集中在 `src/management.py`、`src/management.js` 与 `src/management.css`；沿用既有页面、HTTP 服务与备份模块，没有引入新框架或第三方依赖。

第三方教程视频、字幕和本地参考素材不随仓库发布，源教程见 [Bilibili 视频](https://www.bilibili.com/video/BV1Qfg56sEfb)。

## 测试

以下回归检查不会占用端口，也不修改正式数据库。Python 测试使用 `tests` 内临时数据库；前端测试使用内存数据和模拟网络。

```powershell
python -B tests/run_all_offline.py
python -B tests/test_management.py
python -B tests/test_storage_settings.py
python -B tests/test_launcher.py
node tests/test_frontend.cjs
node tests/test_management.cjs
node tests/test_github_frontend.cjs
node tests/test_github_async.cjs
node tests/test_settings.cjs
```

Node 仅用于前端开发测试，不是应用运行依赖。离线测试覆盖真实路由处理器及数据库操作，不代替浏览器与真实 GitHub 网络端到端验证。

如需实际 HTTP 集成测试，先停止应用并确保 58061 端口空闲，再运行：

```powershell
python -B tests/test_server.py
```

## 设置与恢复保护

设置页区分本地服务、GitHub 配置和手动联网验证，显示当前实际数据库位置、项目 / 任务 / 需求 / 缺陷数量、仓库分支数、最近同步及备份生成时间。支持复制位置、三种主题的明确选中标记，低频说明默认折叠。

- 项目管理备份（`flow-backup-v2`）包含项目、任务、需求和缺陷。恢复后保留 GitHub 快照并重新绑定相同 ID 的项目，不存在的项目改为仅跟踪仓库。
- 完整工作空间备份（`flow-workspace-v3`）还包含 GitHub 账号名称、仓库分支关联、最近提交摘要及最多 500 条活动。不含令牌、仓库源码、浏览器主题或导出历史。
- 旧版 `flow-backup-v1` 和 `flow-workspace-v2` 可导入，但它们不含需求和缺陷。恢复预览明确提示继续会清空这两类现有记录；确认前请核对范围，恢复前完整安全副本保留这些记录。
- 新版备份需使用本版或更新版 Flow 恢复，旧版程序会拒绝未知格式，避免静默丢失新数据。
- 恢复前预览覆盖范围与失效关联，确认后在数据库旁的 `<数据库名>.backups` 目录原子保存完整安全备份。备份写入失败则取消恢复，数据库写入失败则整笔回滚。
- 单份备份上限 64 MB；项目最多 1000 个，任务、需求、缺陷各最多 20000 条，完整备份最多 1000 条仓库分支关联。安全备份不会自动删除，可能包含私有仓库摘要，应妥善保护并另存到其他磁盘。

升级历史见“文档”目录；当前管理功能与备份行为以本 README、使用说明和《项目工作台升级》为准。

## 数据与安全边界

默认数据保存在项目根目录 `data/flow.sqlite3`。设置页支持选择文件夹或输入绝对路径迁移完整数据库，校验成功后立即生效，保留原库和原安全备份，不覆盖目标文件。新位置记在 `data/storage.json`，重启自动读取；位置失效时报错而非静默新建空库。也支持 `--db` 临时覆盖路径。数据库、自动备份和导出文件已通过 `.gitignore` 排除。请通过“工作空间设置”定期导出备份；恢复会替换对应范围的数据。

此工具仅监听 `127.0.0.1`，没有用户登录或团队权限体系。不要直接暴露到公网或企业局域网。另一设备请使用 With 的应用预览，或将完整源码复制到该设备运行。
