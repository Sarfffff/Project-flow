# GitHub 工作台性能优化

本文保留性能升级时的测试记录；当前统一入口和连接方式以同目录《设置与入口升级》为准。

日期：2026-09-11

## 本次改动

- 复用仓库列表中的元信息，省去从列表打开仓库时的一次网络请求。
- 并行加载分支和提交，单个区域完成后立即展示。
- 后端增加 30 秒内存缓存，上限 128 项、16 MiB 序列化内容，不持久化源文件或差异。
- 按令牌指纹、用户名、接口和查询参数隔离缓存；同一有效代际下的相同并发读取共用一次远程调用。
- 仓库列表、提交、目录、文件和提交详情支持显式刷新。刷新、重新连接和同步会失效旧缓存；较早在途请求不会重新填入已失效缓存。
- 分区加载取代整页禁用。加载新内容时保留已有文件/提交；切换仓库、分支、目录及提交详情时取消过时读取，并检查响应是否仍属于当前视图。
- 写入和同步仍防重复操作；不修改任务、项目数据库结构，不新增第三方运行依赖。

- 为避免中断当前服务及丢失内存令牌，没有停止或重启服务。

- 本轮未给出实际端到端加速倍数。前端并行已实现，但正在运行的 Python 进程尚未加载新增缓存代码，因此不能声称当前后端已获得缓存加速。

## 如何生效

1. 当前项目目录中的代码已更新。刷新浏览器可使用新版前端的并行加载和局部加载。
2. 要启用后端缓存，在本机原服务终端按 Ctrl+C 停止服务。
3. 双击项目根目录的“打开Flow.cmd”，在工作空间设置中重新输入只读令牌；请勿将令牌发送到聊天中。
4. 服务启动后刷新 GitHub 工作台，再次打开刚浏览过的目录或提交可使用 30 秒缓存。
5. 要强制获取最新内容，使用“刷新仓库”“在线历史”“刷新当前内容”或“刷新详情”；“同步提交”始终请求 GitHub。

也可以在项目根目录运行：

```powershell
python -B src/server.py --port 58061 --github-login
```

现有数据库保持原位，不需要重新创建项目或任务。分发包不包含 data、令牌、Git 历史和本地仓库内容；在新目录解压运行会创建空数据库。如更新原目录，先停服，将源码覆盖到原目录并保留原 data 目录。
