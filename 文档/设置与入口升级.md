# 设置与入口升级

日期：2026-09-11

## 唯一打开入口

项目根目录只保留 `打开Flow.cmd`。桌面“Flow 项目管理”快捷方式继续指向此入口。已运行则直接打开页面，未运行则启动服务；不会强行关闭其他程序。

已移除重复的 `启动项目.cmd`、`启动GitHub私有访问.cmd` 和 `Flow项目管理.url`。账号连接统一放在应用设置，不再使用单独的 GitHub 启动入口。底层命令行选项保持兼容。

## 数据库位置

进入“工作空间设置 → 更改数据库位置”，点击“选择文件夹”或输入新的数据库完整绝对路径，确认后迁移。文件夹选择窗口在运行项目的 Windows 电脑上显示；在其他设备使用预览时，可手动输入运行电脑上的路径。

- 目标文件夹须存在，数据库后缀为 `.sqlite3`、`.sqlite` 或 `.db`。
- 仅支持本机磁盘，不允许网络共享或映射网络盘；建议避开云同步目录。
- 使用 SQLite 在线备份接口复制完整数据库，包含已经提交的 WAL 数据。
- 校验完整性和外键后才保存配置、切换路径；不覆盖已有文件。
- 保留原数据库及原安全备份。迁移失败仍使用原位置。
- 新位置记录在项目 `data/storage.json`，下次启动自动使用。若路径丢失，启动报错而不是静默新建空库。
- 其他请求正在使用数据库时，本次迁移会提示稍后重试；日常 GitHub 读取仍并行执行。
- 更改位置用于迁移当前工作空间，不用于直接接入来源不明的数据库。导入其他工作空间请用备份恢复。

升级过程中未改变用户数据库位置，并在 `data/upgrade-backups` 保存了一份升级前 SQLite 副本。

## GitHub 连接

进入“工作空间设置 → 配置 GitHub 连接”：

1. 公开账号：填写 GitHub 用户名，点击“验证并连接”。
2. 私有仓库：选择只读令牌模式，输入 Fine-grained token；用户名可留空自动识别。令牌应仅授予所需仓库 Contents / Metadata 的 Read-only 权限。
3. 验证成功立即生效，无需停止服务；工作台中的“管理 GitHub 连接”跳转设置页。
4. 令牌输入提交后清空，服务端只保留进程内存，不回显、不写数据库、浏览器存储或备份。服务重启后需重新输入。
5. 验证失败不会覆盖现有连接。切换账号或断开不会删除本地仓库关联与提交快照。断开不等于在 GitHub 网站撤销授权。

不要将令牌发送到聊天、源码或启动脚本。该应用是单用户本地服务，不要通过不可信代理访问或对公网开放。

## 体验优化

设置表单与状态刷新区域分离，刷新状态不会擦掉正在填写的路径或令牌。迁移和连接过程提供操作中反馈、防重复提交和失败提示，低频设置使用折叠区，小屏输入区自动纵向排列。切换连接时会清空旧缓存和工作台会话，并防止过时账号请求覆盖新状态。

## 验证范围

自动化验证使用临时数据库和模拟 GitHub，不使用真实令牌，不迁移正式数据库。覆盖已有后端业务、GitHub 缓存和并行读取、设置交互、目标文件保护、配置写入失败回退、路径失效、并发操作门禁、来源检查、令牌失败保留旧连接与断开连接。

本机服务已重启，固定使用 58061；页面和健康接口 HTTP 200，新设置资源可读取。真实文件夹选择及私有仓库授权仍需用户在本机操作。内置预览遇到企业登录，需要用户在手机 iOA 人工确认，未将旧页面截图作为新版视觉验收结果。
