# GitHub 工作台

## 能做什么

- 按页列出个人账号拥有且授权可见的仓库，显示公开/私有、语言及描述。
- 也可手动输入 `owner/repository`，读取公开仓库或令牌授权的其他仓库。
- 浏览分支、目录与 UTF-8 源文件。Markdown、HTML 均按纯文本显示，不执行仓库中的脚本。
- 查看分支提交历史，筛选当前账号作为作者的提交，并按页查看提交的文件改动和文本 diff。
- 将仓库分支关联到本地项目，保存最近提交快照并标记本次新出现的提交。
- 从提交详情创建本地任务草稿，自动填写提交消息、原始链接、负责人和关联项目；需要用户点击保存，不会自动标记任务完成。
- 可勾选每 5 分钟同步当前已关联分支，仅在工作台页面可见时工作，默认关闭。没有系统定时任务或后台常驻同步。

本应用只调用 GitHub GET 接口，不修改仓库、提交、权限、Issue 或 Pull Request。不需要 Node 或第三方 Python 依赖来运行。

## 响应速度优化

- 从列表打开仓库时复用仓库信息，分支与提交并行请求；各自完成即可显示，不再等待全部响应。
- 仓库列表、分支、提交、目录、文件和差异使用后端 30 秒内存缓存，最多 128 项、16 MiB JSON 内容；按令牌指纹、账号及完整查询参数隔离。源文件与差异不落盘，相同并发读取合并，失败不缓存。
- 点击“刷新仓库”“在线历史”“刷新当前内容”“刷新详情”均强制读取最新数据并使旧缓存失效。“同步提交”始终直连 GitHub，并清理读取缓存。重新连接账号也清理缓存。
- 缓存命中期间可能显示 30 秒内的旧内容；权限变更亦需要缓存过期或手动刷新后确认。缓存失效不会回退展示旧权限数据。
- 各区域独立加载，已有内容继续显示；切换仓库、分支或文件时取消过时读取，旧响应不会覆盖新选择。关联写入和同步仍防止重复操作。
- 前端刷新页面即可使用；后端缓存需停止旧服务，再通过“打开Flow.cmd”启动并在设置中重新输入令牌后生效。不要在聊天中提供令牌。此次更新不修改项目与任务数据。

## 公开仓库

1. 启动应用，进入工作空间设置的配置 GitHub 连接。
2. 输入 GitHub 个人用户名，例如 `Sarfffff`，点击验证并连接，再进入 GitHub 工作台。
3. 选择仓库及分支，浏览提交或切换“仓库文件”。
4. 选择本地项目并点击“开始跟踪”，建立该分支的首次快照。

公开模式不需要令牌，但 GitHub 按出口 IP 限制未授权请求额度。限额耗尽时页面会提示，请等待重置或使用只读令牌，不会把访问失败伪装为空仓库。

## 私有仓库与只读令牌

在 [GitHub 令牌设置](https://github.com/settings/personal-access-tokens/new) 创建 Fine-grained personal access token：只选择需要读取的仓库，设置合理有效期，并授予 Contents: Read-only、Metadata: Read-only。不要授予写权限。组织仓库可能需要组织批准或 SSO 授权。

在工作空间设置的配置 GitHub 连接中选择只读令牌模式，在本机设置页密码框输入令牌后点击验证并连接。用户名可留空自动识别，验证成功立即生效。令牌仅保留后端进程内存，不回显、不写入浏览器存储、数据库或备份；服务重启后重新输入。

验证失败保留原连接。断开连接清除本次会话凭据并保留关联和快照；如需撤销授权，请在 GitHub 撤销令牌。不要将令牌发到聊天中。

本应用只读不代表一个高权限令牌自动降权，必须由用户在 GitHub 设置最小权限。Windows 单人本地模式没有应用登录，拥有本机访问权的进程仍能访问已授权服务，请勿暴露到公网、共享网络或不可信预览渠道。

## 跟踪语义

- 以指定分支当前可达的 commit SHA 为依据，不是全账号 Push 事件监控，也不按 Push 操作者计数。
- 首次同步建立基线，不将全部历史标记为新增。
- 后续同步与上一次最近 100 条快照比较，新出现的 SHA 才标记为本次新增。
- 同步失败保留旧快照，可以点击已关联分支旁的“快照”离线查看摘要。文件内容和 diff 仍需要联网。
- “只看当前账号作为作者的提交”依赖 GitHub 关联的作者身份；提交邮箱未关联账号、他人代推或共同作者不一定符合该筛选。
- 最近 100 条仅用于轻量跟踪，不是完整审计历史。如果间隔期间产生超过 100 条提交，或 force-push / rebase 改写历史，可能出现缺口或重新出现的提交。页面会对检测到的无重叠快照提示；完整历史请使用“在线历史”分页浏览。
- 多窗口的同步请求使用后端锁防止并发覆盖；项目关联修改为最后成功写入生效，不使用任务数据的 revision。请避免多个窗口同时编辑同一关联。

## 内容与数据边界

文本文件预览上限 512 KB，支持 UTF-8/UTF-8 BOM；大文件、二进制、非 UTF-8、子模块和显式符号链接提供提示。GitHub Contents API 单目录最多列出 1000 项。GitHub 有时会将仓库内符号链接直接返回为文件内容，系统只显示 GitHub 响应，不在本机解引用。

提交文件列表每页 30 个，受 GitHub 超大提交最多 3000 文件限制。单文件 patch 最多显示 100000 字符；GitHub 没有提供 patch 时明确提示。仓库列表每页 30 项，分支每次加载 100 项，均可继续翻页/加载。

仅保存 GitHub 用户名、仓库分支关联、最近同步时间及最多 100 条提交摘要到原 SQLite 数据库。源文件和 diff 不持久化缓存。提交摘要可能包含私有信息，应像业务数据一样保护数据库，已有忽略规则会排除数据库文件。

项目备份只覆盖项目与任务；恢复后保留快照并重新绑定仍有效的项目。设置页另提供完整工作空间备份，包含账号名称、关联和快照，不含令牌或仓库源码。

移除仓库关联会删除该分支本地快照，不影响 GitHub 或本地任务。删除本地项目会解除仓库的项目关联，保留仓库跟踪记录。
