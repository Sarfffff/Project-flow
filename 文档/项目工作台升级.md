# 项目工作台升级

日期：2026-09-11

## 布局与入口

根据参考图片增加项目管理能力，同时遵循“并非每项功能都需要新增页面”的补充要求。

| 位置 | 内容 | 操作方式 |
| --- | --- | --- |
| 原总览，现仪表盘 | 任务概况、项目进度、需求跟进和未关闭缺陷摘要 | 点击摘要进入对应工作台页签 |
| 侧栏项目工作台 | 计划管理、需求管理、缺陷管理 | 同一个页面框架的三个页签，不增加重复侧栏入口 |
| 计划管理右上方 | 列表、看板、甘特图 | 同一批计划任务的三种视图，搜索和主要筛选共享 |
| 各模块列表上方 | 搜索、状态、优先级、项目与排序 | 筛选不遮挡主要操作；缺陷另有严重程度筛选 |
| 模块标题右侧 | 新增任务、需求或缺陷 | 编辑弹窗；详情不另开页面 |
| 选中记录后 | 批量状态与删除 | 只在有选择时显示，删除前确认 |
| 工作空间设置 | 数据库位置、GitHub 连接、备份恢复 | 低频设置保留在原位置 |

从具体项目进入工作台时，切换页签保留项目范围。链接刷新后可恢复当前页签；甘特图地址表示计划视图，不是独立业务页面。

## 本版能力

计划任务继续使用原数据表，保留负责人、优先级、状态、进度、起止时间、分页、排序和拖拽看板，列表补齐起止日期显示。

甘特图直接读取计划任务起止日期，提供日、周、月尺度，时间段前后切换、任意起始日期、回到今天、任务定位和点击条形编辑。月尺度采用 30 天刻度并明确标注。无完整起止日期的任务保留显示并提示补充；区间外任务显示定位入口，不假装已经排期。每页最多 40 项任务，时间轴宽度有界，极端长日期跨度不会生成数千个日期节点。甘特图不提供拖动调整日期、任务依赖计算或关键路径分析。

需求字段包含名称、描述、所属项目、负责人、优先级、状态、截止日期和验收条件。状态为待评审、已确认、进行中、待验收、已完成。

缺陷字段包含名称、描述、所属项目、负责人、优先级、严重程度、状态、截止日期、发生环境 / 版本、复现步骤、预期结果、实际结果 / 验证记录。状态为待处理、修复中、待验证、已关闭；允许重新打开。严重程度为致命、严重、一般、轻微，与优先级独立。

需求和缺陷均支持创建、编辑、删除、搜索、组合筛选、排序、分页、行内状态修改、批量状态与批量删除。状态由用户确认，不从 GitHub 提交数自动推断。

仪表盘保留任务完成率原口径，需求和缺陷使用独立摘要，避免混入原任务进度分母。页签数字表示当前范围未完成 / 未关闭的记录数。

## 数据安全

- 新增 requirements 与 defects 表及项目索引，保留原项目、任务、GitHub 数据与数据库位置。
- 含任务、需求或缺陷的项目不允许直接删除，需要先移动或删除关联记录。
- 所有写入沿用本地来源检查、JSON 校验、全局 revision 冲突保护与事务回滚；需求和缺陷表单保存使用打开时版本，避免已刷新的界面掩盖旧编辑冲突。
- 批量操作全有或全无，不因部分记录缺失留下半更新状态；完成时间在关闭 / 完成时保存，重新打开时清除。
- 项目管理备份改为 flow-backup-v2，完整工作空间备份改为 flow-workspace-v3，包含需求和缺陷全部字段。
- 旧版项目备份和完整工作空间备份可导入，但会将需求和缺陷恢复为空；预览明确告知覆盖范围，执行前安全副本仍包含恢复前全部新数据。
- 新版备份不会伪装旧格式，以免旧程序静默遗漏需求和缺陷。新格式需本版或更新版恢复。
- 本次本地升级前使用 SQLite 在线备份保留完整数据库副本。浏览器验收使用独立测试库，正式库不加入演示记录。

## 使用与升级

启动后进入“项目工作台”。计划管理右上方切换到甘特图；上方页签切换需求或缺陷。也可从左侧某个项目进入，限定该项目的管理记录。

升级其他安装时先在旧服务导出完整备份，然后停止旧服务，复制新版源码和说明，保留原 data 目录以及外置数据库，重启并刷新。GitHub 私有令牌仅保存在进程内存，重启后需要在设置中重新输入。

本版只补参考图中的基础管理能力和对应排版，不增加团队权限、子任务依赖、审批、工时或自动 GitHub 验收，也不自动向远端仓库推送代码。
