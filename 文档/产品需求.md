# Flow 产品需求与交互规范

## 1. 功能需求

目标用户：同时推进多个项目的个人。核心目标：让项目、任务和优先级可见，让每次修改真正保存，让完成情况自动汇总。

核心实体为项目和任务。项目包括名称、描述、标识色；任务包括标题、描述、所属项目、负责人、优先级、状态、进度、开始/截止日期及创建、更新、完成时间。

主流程：创建项目 → 添加任务 → 分配负责人和时间 → 更新状态与进度 → 查看统计 → 导出备份。

所有工作空间初始数据为空，不用随机数、静态图表或伪造任务填充界面。用户未提供真实数据时展示零值和引导空状态。

## 2. 需求精简

首版保留项目/任务 CRUD、筛选搜索、列表/看板、批量操作、统计、主题、备份恢复。

首版不做多租户、复杂角色权限、登录注册、在线协作、审批流、聊天、附件存储、外部平台同步和通知推送。负责人为手工输入文本，不暗示真实账户体系。

不同于视频中“个人用不用管安全性”的说法，仍保留输入校验、SQL 参数化、用户文本转义、删除确认、请求来源检查和并发冲突保护。部署范围限定本机。

## 3. 视觉与交互

产品名 Flow。默认深空紫主题，配深灰层级面板、低对比边框、紫色主操作、状态语义色；附带晨光白和极光绿。不要使用大面积高亮渐变影响阅读。

左侧固定导航，顶部位置导航和连接状态，主区按标题、核心指标、分析图、任务工作台、项目进展与动态分层。屏幕变窄时导航折叠为可切换侧栏，表格水平滚动，看板分栏横向滚动。

主操作为“新建任务”；项目创建为次级操作。任务与项目编辑使用模态框；输入字段有标签、长度限制，必填字段为标题/名称、负责人、优先级。保存中禁用重复提交，保存成功后关闭并提示；失败则保留表单内容和错误说明。

任务表格支持可见页全选、分页、状态直接修改。看板四列允许拖放，状态改变后实时重新统计；键盘与触屏可通过编辑表单完成等价操作。

删除任务、批量删除、删除空项目、备份恢复均需确认。项目非空时禁止删除，避免不透明的级联删除。

图表不依赖外部服务：状态图使用 CSS conic-gradient，优先级与趋势使用真实数量计算的条形图。减少动画偏好启用时取消过渡。

## 4. 生成与实现约束

技术栈：原生 HTML/CSS/JavaScript + Python 3.10+ 标准库 HTTP 服务 + SQLite。无外部运行依赖，无编译构建过程。因为依赖实际后端 API，必须通过服务访问，不能按纯静态项目运行。

编码统一 UTF-8。所有输入都经过服务端校验；SQL 值参数化；静态资源通过显式白名单访问，数据库和源码不可通过HTTP读取。请求体有大小限制，写入请求需要 application/json、专用请求头和数据版本。

SQLite 写入采用事务；每次成功变更递增 revision。客户端提交必须携带读取时版本。版本冲突返回 409，阻止静默覆盖。备份恢复为全量替换事务，任何一条数据校验失败都必须回滚全部变更。

数据库保存在应用目录 data/flow.sqlite3。浏览器 localStorage 仅保存主题偏好。导出备份包括项目、任务及必要时间信息，恢复会重置活动历史，不包含主题。

## 5. 功能迭代与验收

- 初次启动无业务数据且不报错，空统计与引导可见。
- 项目、任务可以实际创建、编辑、删除；刷新和重新启动后记录仍存在。
- 不合法优先级、状态、日期、超长名称、越界进度、无效项目引用必须被拒绝。
- 已完成任务进度为 100%，重新打开后取消完成时间且进度小于 100%。
- 看板拖放及列表状态操作调用同一后端存储逻辑。
- 搜索、筛选、排序与分页影响任务结果；批量操作有明确选择与确认。
- 未完成的过期任务显示逾期语义色；图表按明确范围和统计口径计算。
- 三主题可切换，刷新保留；桌面和小屏布局可用。
- 非空项目删除被阻止；请求失败显示提示，不伪装保存成功。
- 导出/恢复可往返；错误备份、重复ID和无效引用不损坏已有数据。
- 多窗口版本冲突不会静默覆盖；用户文本不会执行为 HTML 或脚本。
- 交付源码、运行说明、需求规范、自动化测试与源码压缩包。

后续可在明确需求后扩展里程碑、甘特图、任务依赖、团队认证、自动备份与协同，不在首版中生成无功能占位入口。
